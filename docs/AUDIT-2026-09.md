# Sutra audit & revamp — September 2026

## What was wrong

### The repo didn't build
The committed tree was a partial snapshot of a larger local tree:

- **About 30 imported modules were never committed.** These included `lib/auth`, `captureGuard`, `mcpBridge`, `nativeChrome`, `local/coalesce`, `minutes`, `refinement`, `devSeed`, `components/AccountStep`, `ScrollMemory`, `GraphView`, `settingsKit`, all of `pages/settings/*`, `SignIn`, `landing/*`, `landing-pro/*` and `backup`.
- **`tsc` failed with about 45 errors**, and 7 of the 13 test files could not load.
- **`package-lock.json` was out of sync** with `package.json`, so `npm ci` failed.
- **The backend proxy imported `app/proxy_gate.py`, which didn't exist**, so the proxy couldn't start.

### Schema drift
The repo layer reads and writes tables and columns that no committed migration creates:

- tables: `priors`, `projects`, `project_people`, `minutes`
- columns: `text_clean`, `refined`, `is_meeting` and `project_*`

A comment in the code mentions "pre-v9 rows", so local databases in use are *ahead* of the committed `SCHEMA_VERSION = 4`. A plain versioned migration can't repair that.

### Bugs in shipped logic
| Bug | Effect |
|---|---|
| Re-extracting a memory ran `DELETE` on the **contentless** FTS5 table | SQLite rejects that, so every reprocess/"retry" of a memory threw |
| `extractConversation` inserted action items without clearing the old ones | Every re-extraction duplicated them |
| Topic-shift segmentation also ran on meeting recordings | A 1-hour call was split into several "conversations" |
| Meeting windows were time-stamped when the window *finished* | Transcript times were about 90 s late |
| The AudioWorklet was loaded from the absolute path `/worklets/…` | Fails under `file://`, so capture was broken in the **packaged** desktop app |
| `BrowserRouter` under `file://` | Routing was broken in the packaged desktop app |
| Stereo "multichannel" meeting audio was sent to the OpenAI STT provider | That provider ignores channels, so "Me vs. others" attribution silently didn't work with the default provider |
| No quit/close handling | Closing the desktop window killed an in-progress recording |

## What changed

### UI: rebuilt, minimal, modelled on Aside
- **Layout:** one sidebar and one reading pane.
  - The sidebar has search, a meeting list grouped into *Today / This week / This month / <Month>*, a settings button and **Start recording**.
  - The pane shows the title, a one-line gist, a **Style** picker (Brief / Detailed), tags, and **Notes | Transcript** tabs.
  - Notes are split into Summary, Decisions, Action items (with checkboxes) and Open questions.
  - An **Ask about this meeting…** bar sits at the bottom, with Copy, Export (.md) and Delete.
- **Transcript:** click a speaker to rename them, or choose "This is me". A **Refresh notes** button re-runs extraction so the notes pick up the new names.
- **Live view:** a clock, an input level and the transcript as it arrives.
- **Search:** results filter as you type. Press Enter to ask a question across all meetings, with links to the meetings that support the answer.
- **Settings:** one sheet for your name, microphone, headphones/speakers, transcript language, meeting detection, macOS permissions and theme.
- **Themes and layout:** dark and light themes. On phone widths the layout switches to list ⇄ detail.
- **Removed from the app shell:** Graph, Projects and the landing pages. Their code was mostly missing anyway.

### Desktop app: automatic meeting detection and the pill
- **Detection** runs in `electron/meetingDetector.ts` and polls every 3 s. The decision rules are pure functions in `src/shared/meetingRules.ts` and are unit-tested.
  - **Windows:** reads which app is using the mic from the privacy consent store in the registry.
  - **Linux:** reads the same from PulseAudio/PipeWire via `pactl`.
  - **macOS:** there is no mic-consumer API, so it checks the open tabs of running browsers via AppleScript (Meet, Zoom web, Teams, Slack huddles, Webex, Whereby, Jitsi, Around, Gather). It also checks window titles (once Screen Recording is allowed) and Zoom's `CptHost` process.
  - **Debounce:** a call must be seen on 2 checks before it shows and missed on 3 before it ends. Dismissing hides the prompt for that call only.
- **The pill** is a non-activating window, always on top at the top-centre of the screen and visible on all Spaces. It shows:
  - "Google Chrome in call · ● Record ×" when a call is detected;
  - a live timer and level with **Stop** while recording;
  - "Writing notes…", then "Notes ready · Open".
- **Recording is started from the main window's renderer** via `executeJavaScript(…, userGesture=true)`, because `getDisplayMedia` loopback needs a user activation.
- **When the recorded call ends, recording stops automatically** (you can turn this off).
- **Closing the window hides it**, so detection and recording keep running. A tray icon offers Start/Stop, the detection toggles and Quit. Quitting mid-recording stops cleanly first.
- **macOS packaging:** hardened-runtime entitlements (mic, Apple Events) and the Info.plist usage strings were added.

### Pipeline
- **Per-channel transcription (the default).** Each ~90 s window is split into your mic and the call audio. Each side is downsampled to 16 kHz mono and transcribed separately, and a side with no speech is skipped. This gives exact "Me vs. others" attribution with any STT provider, cuts upload size by about 6×, and saves the cost of silent channels. The old stereo mode is still available as `channelMode: "stereo"`.
- **A meeting recording is one conversation.** Its session is tagged `kind='meeting'` with the app that hosted the call.
- **Extraction** (`extract-v5`) now also produces a one-line subtitle and open questions.
- **Detailed notes** are generated on demand and cached in a new `notes` table. The cache is cleared when a meeting is re-extracted.
- **Per-meeting Q&A** (`askMeeting`) answers from that meeting's notes and transcript.
- **Schema v5** adds the missing tables. `ensureSchema()` runs on every database open, whatever `user_version` is: it creates missing tables and adds missing columns. This is idempotent and safe on divergent local databases.
- **FTS5 fix:** memories are removed from the index with the FTS5 `'delete'` command. Action items are replaced, not appended, on re-extraction.
- **Backend:** added a minimal `proxy_gate.py`. It is open in dev, supports the optional shared secret and optional HS256 JWT verification, counts usage in memory, and enforces no quotas.

## Verify on a Mac (can't be tested in CI)
1. `npm run dev` in `frontend/`. Join a Google Meet in Chrome. Within about 6 s the pill should appear. The first time, macOS asks whether Sutra may control Chrome — allow it.
2. Allow **Screen & System Audio Recording** for Sutra. System-audio loopback uses ScreenCaptureKit, and `main.ts` enables the Chromium flags that gate it. If the other side is silent in transcripts on your Electron/macOS version, upgrade Electron — macOS loopback support landed in recent releases.
3. Click Record, talk, then click Stop. The notes should open.
